# Validation snapshot

Compatibility and coverage measured on 2026-11-02. The exact-render gate still
fails. The historical cold-start measurements below were recorded on 2026-11-01.

## Build

All 2,722 tests pass across Java 11 and Java 25 on macOS. The same 1,361 tests pass
on each JDK in isolated Linux containers. The suite includes 1,128 exact PNG/SVG
comparisons of project-authored fixtures. It covers encoding, shapes, connectors,
options, text, allocation limits, unavailable PNG encoders, write failures and
concurrent rendering. Renderer coverage is 99.6% of lines and 98.0% of branches,
with no exclusions. `check` requires at least 99% line and 97% branch coverage.
Library classes target bytecode version 55 and depend only on
`java.base` and `java.desktop`. Release JARs include the MPL-2.0 licence.

## Rendering

The pinned corpus contains 240 unique inputs from 846 source entries. Its largest
collection is `linux-kernel-labs/linux-kernel-labs.github.io`, with 75 unique inputs.
All 1,920 cases completed across both formats and four option variants:

| Format | Exact matches | Differences |
| ------ | ------------- | ----------- |
| PNG    | 902           | 58          |
| SVG    | 890           | 70          |
| Total  | 1,792         | 128         |

This improves the initial 76 exact matches; complete compatibility remains unmet.
Complex boundaries, text layout, dashed curves and combined features still differ.
The PNG oracle now invokes the public raw-text API in an isolated JVM. This removes
PlantUML preprocessing from the comparison and eliminates all 40 dimension
mismatches. Both renderers receive identical input whitespace.

Comparison environment: macOS 26.7.2, aarch64, Temurin 25.0.5+8-LTS,
`rsvg-convert` 2.63.4. The cold-start measurements below use the earlier JDK.
The local [comparison report](../build/comparison/index.html) contains reference
images, actual images, overlays, and differences. It is generated by the
[comparison workflow](COMPATIBILITY.md).

## Cold start

Environment: macOS 26.7.2, aarch64, 16 processors, Temurin 25.0.3+9-LTS.
Each scenario used 30 interleaved fresh JVMs per implementation. Timing includes
encoding; memory uses `/usr/bin/time -l`. Cells show traceur-ditaa / reference;
RSS is the median of per-process peaks.

| Boxes | Format | Median ms      | p95 ms          | RSS MiB       |
| ----- | ------ | -------------- | --------------- | ------------- |
| 1     | PNG    | 950.7 / 1048.3 | 1969.1 / 2231.5 | 215.0 / 234.9 |
| 1     | SVG    | 982.6 / 1032.0 | 1062.9 / 1052.2 | 210.0 / 219.8 |
| 10    | PNG    | 944.1 / 1093.1 | 984.3 / 1201.9  | 216.6 / 339.4 |
| 10    | SVG    | 911.0 / 1008.2 | 1758.3 / 1915.4 | 209.7 / 307.5 |
| 50    | PNG    | 998.3 / 1560.4 | 1192.3 / 1669.9 | 230.0 / 847.4 |
| 50    | SVG    | 909.1 / 1441.9 | 952.0 / 1478.9  | 216.3 / 832.3 |

Median latency and peak memory are lower in all scenarios. The one-box SVG p95
is 10.7 ms higher, so the strict gate fails. Performance remains provisional while
outputs differ. Warm throughput was not measured.
